# План доработки документации до статуса Production-Ready и новые прототипы

## 1. Контекст
Проект содержит проработанную архитектурную базу (ADR, C4, OpenAPI, ERD, Screen Contracts). Для непосредственного старта разработки бэкенда и фронтенда не хватает нескольких критических спецификаций и вспомогательных артефактов (Seed data, формулы тарификатора, JWT-схемы, Offline sync для водителей).

---

## 2. Поэтапный план доработки

### Блок 1: Спецификации, необходимые для старта разработки бэкенда
- [x] `[TASK-040]` **Тестовые фикстуры и Seed-данные (`docs/21-testing/test-data.md`)**:
  - Готовые SQL/JSON дампы для локального окружения (`docker compose up`):
    - 3 тестовые организации (Shipper, Carrier, Forwarder) с ИНН и тирами.
    - 5 тягачей, 5 полуприцепов, 5 водителей.
    - Геозоны ключевых терминалов (Москва-Север, Шушары СПб, Казань).
    - Набор активных грузов и заказов в разных статусах.
- [x] `[TASK-041]` **Формула динамического тарификатора фрахта (`docs/12-finance/pricing.md`)**:
  - Точная математическая модель расчета рекомендованной ставки:
    - Базовая ставка за км по направлениям (Truckload Cost per km).
    - Коэффициент типа кузова (Реф +25%, Изотерм +10%, Тент 1.0).
    - Платные дороги (М-11, М-12) и система "Платон" (3.05 ₽/км).
    - Сезонный коэффициент и спрос/предложение в регионе отправления.
- [x] `[TASK-042]` **Спецификация токенов авторизации и структуры JWT (`docs/14-api/authentication.md`)**:
  - Формат полезной нагрузки (JWT Claims): `user_id`, `org_id`, `roles`, `permissions`, `tier`.
  - Ротация refresh токенов, TTL (Access: 15 мин, Refresh: 30 дней) и механизм отзыва через Redis blacklist.
- [x] `[TASK-043]` **Dead-Letter Queue и Retry Policy в Kafka (`docs/14-api/asyncapi/events.yaml` и `docs/03-architecture/adr/0004-event-streaming.md`)**:
  - Регламент обработки сбойных сообщений: 3 повтора с экспоненциальным backoff (1с, 5с, 30с) -> перенос в `.dlt` с алертом.
  - Правила формирования `partition_key` для гарантированного порядка сообщений.
- [x] `[TASK-044]` **Протокол Offline-First синхронизации для мобильного приложения водителя (`docs/10-location-and-routing/gps-ingestion.md` и `docs/20-ui/screen-contracts/driver-active-trip.md`)**:
  - Локальное сохранение точек в SQLite при отсутствии сети на трассе.
  - Протокол пакетной досылки при восстановлении GSM-связи без дублирования.
