## Контекст

Ты проектируешь техническую документацию для **современной цифровой логистической платформы** — маркетплейса грузоперевозок.

Платформа — это **Logistics Marketplace + Transport Management + Real-Time Visibility + Trust Network + Integration Platform**, а не просто «сайт с грузами и машинами».

Референсы бизнес-функциональности (изучи публичные описания, не копируй реализацию):

- **ATI.SU** — грузы, машины, заказы, фирмы, площадки, тендеры, GPS, рейтинги, API
- **Trans.eu** — public/private freight exchange, trusted networks, automatic assignment, eCMR, TMS integration
- **TIMOCOM** — Freight Exchange, Transport Orders, Live Tracking, REST API
- **DAT** — load board, carrier ratings, company scores, market rates, analytics
- **Uber Freight** — digital booking, shipment execution, multi-stop, real-time visibility, pricing

Основной бизнес-поток:

```
Shipper → Load → Public/Private Market → Matching/Negotiation →
Transport Order → Vehicle + Driver → Execution →
GPS Tracking + Documents → Delivery → Settlement →
Rating/Reputation → Trust Network
```

Обратный сценарий: Carrier публикует свободную машину → Shipper находит и бронирует.

Участники рынка:

- грузовладельцы (shippers)
- экспедиторы (freight forwarders)
- перевозчики (carriers)
- транспортные компании
- автопарки, водители, диспетчеры
- сотрудники компаний, доверенные контрагенты
- администраторы платформы
- внешние TMS/ERP/WMS системы

**Язык документации — русский. Диаграммы — Mermaid.**

#### 2. Детальное описание каждого актора

Для каждого актора создай подраздел с:

**Shipper / Грузовладелец:**

- Роль: компания или подразделение, которое нуждается в перевозке грузов
- Основные сценарии: публикация груза, поиск перевозчика, переговоры, мониторинг перевозки, подтверждение доставки, оплата
- Ключевые потребности: надёжный перевозчик, прозрачная цена, видимость перевозки
- Уровень доступа: свои грузы, свои заказы, профили перевозчиков (ограниченно)

**Freight Forwarder / Экспедитор:**

- Роль: посредник, организующий перевозку от имени грузовладельца
- Отличия от Shipper: работает с множеством грузовладельцев и перевозчиков, может управлять private marketplace
- Дополнительные возможности: управление контрагентами, тендеры, консолидация грузов

**Carrier / Перевозчик:**

- Роль: компания, осуществляющая перевозку
- Основные сценарии: поиск грузов, публикация truck offer, подача оффера, принятие заказа, назначение водителя/машины
- Дополнительно: управление автопарком, управление водителями, отслеживание своих перевозок

**Transport Company / Транспортная компания:**

- Отличие от Carrier: более крупная организация с несколькими подразделениями, автопарками, диспетчерской службой

**Fleet Manager / Управляющий автопарком:**

- Роль: управление транспортными средствами и их доступностью
- Сценарии: добавление/редактирование ТС, управление доступностью, назначение на маршруты

**Dispatcher / Диспетчер:**

- Роль: оперативное управление перевозками
- Сценарии: мониторинг активных перевозок, работа с исключениями, коммуникация с водителями, перепланирование

**Driver / Водитель:**

- Роль: непосредственный исполнитель перевозки
- Интерфейс: мобильное приложение
- Сценарии: получение задания, навигация, обновление статусов, фото PoD, подпись документов

**Company Employee / Сотрудник компании:**

- Роль: пользователь с ограниченными правами внутри организации
- Доступ определяется ролью в организации

**Trusted Counterparty / Доверенный контрагент:**

- Роль: контрагент с установленными доверительными отношениями
- Доступ к private marketplace, приоритет в matching

**Platform Admin / Администратор платформы:**

- Роль: управление платформой
- Сценарии: модерация, верификация компаний, работа с жалобами, аналитика, аудит

**External System / Внешняя система:**

- Типы: TMS, ERP, WMS, GPS-провайдер, платёжный провайдер
- Взаимодействие: через REST API, webhooks, async events
- Авторизация: OAuth2, API keys, service accounts

### Структура документа

#### 1. Обзор бизнес-модели

Платформа монетизируется через несколько потоков дохода.

#### 2. Потоки монетизации

Для каждого потока: описание, кто платит, когда, как рассчитывается.

- **Комиссия с транзакций** — процент от стоимости перевозки при успешном закрытии заказа

- **API-доступ** — тарификация по объёму запросов для TMS/ERP интеграций
- **Верификация** — платная расширенная верификация компании
- **Финансовые сервисы** — комиссия за факторинг, платёжные гарантии

#### 3. Тарифные планы

Описание уровней подписки с лимитами и возможностями.

#### 4. Финансовый поток платформы

Mermaid-диаграмма потока денег:

```
Shipper → [Оплата перевозки] → Платформа → [Удержание комиссии] → Carrier
                                    ↓
                             Комиссия платформы
```

#### 5. Ключевые метрики бизнес-модели

- GMV (Gross Merchandise Value)
- Take rate (% комиссии)
