## Контекст

Проектируем сквозные исполняемые бизнес-процессы (Workflows) и регламенты обработки нештатных ситуаций (из §34 master-prompt).
Диаграммы оформляются в формате diagrams-as-code: **Mermaid** (flowchart TD / sequenceDiagram) или **BPMN-стиль**.

Язык — **русский**.

---

## Задание 1: создай документы Workflows (6 файлов)

Каждый workflow-документ должен содержать:

1. **Цель и бизнес-контекст процесса**.
2. **Участники и дорожки (Swimlanes / Roles)**: Shipper, Carrier, Driver, Dispatcher, System Automations, External Providers.
3. **Mermaid Flowchart диаграмму процесса** со всеми развилками (Exclusive Gateway `X`, Parallel Gateway `+`), событиями-таймерами и граничными событиями ошибок.
4. **Пошаговую спецификацию шагов процесса**:
   - Входные данные шага
   - Ответственная роль / Сервис
   - Выполняемое действие и валидации
   - Создаваемые доменные события
   - Возможные точки отказа и таймауты

### Спецификация файлов:

1. **`load-to-order.md` (От публикации груза до транспортного заказа)**:
   - Создание объявления → Валидация и скоринг → Публикация → Поиск и матчинг → Подача офферов → Торги и согласование условий → Бронирование груза → Формирование договора-заявки → Двустороннее подписание → Создание `TransportOrder`.

2. **`order-execution.md` (Исполнение перевозки от назначения до доставки)**:
   - Назначение ТС и водителя → Подтверждение водителем → Подача под погрузку → Проверка документов и опломбирование → Погрузка → Движение по маршруту (GPS мониторинг) → Прохождение контрольных точек → Прибытие на выгрузку → Выгрузка → Подписание eCMR/PoD → Фиксация успешного завершения рейса.

3. **`tender.md` (Проведение закрытого тендера / торгов)**:
   - Создание тендера с фиксированным дедлайном → Выбор целевого пула перевозчиков → Сбор ставок (открытые / закрытые ставки) → Автоматический скоринг предложений → Выбор победителя (ручной / авто по наименьшей цене) → Автоматическое оповещение проигравших → Создание заказа с победителем.

4. **`carrier-onboarding.md` (Онбординг и проверка перевозчика)**:
   - Регистрация юрлица → Заполнение реквизитов → Автоматическая проверка по базам ФНС/ЕГРЮЛ → Загрузка уставных документов и полисов страхования ответственности (CMR-страхование) → Проверка службой безопасности платформы (KYC) → Присвоение статуса верификации и лимитов.

5. **`document-flow.md` (Электронный документооборот перевозки)**:
   - Формирование электронной транспортной накладной (eCMR / ЭТрН) → Подписание грузоотправителем → Подписание водителем при приемке (ПЭП) → Передача в ГИС ЭПД / оператору ЭДО → Подписание грузополучателем при сдаче → Выпуск закрывающего пакета документов (УПД/Акт, Счет).

6. **`payment-flow.md` (Финансовые взаиморасчеты и факторинг)**:
   - Проверка выполнения условий доставки и валидность PoD → Формирование инвойса → Блокировка/списание средств с грузовладельца (Escrow / Предоплата / Постоплата) → Удержание комиссии платформы → Выплата перевозчику (стандартная постоплата или мгновенная выплата через Факторинг).

## Задание 2: создай `docs/05-business-processes/exception-flows/shipment-exceptions.md`

### Содержимое документа (Регламент обработки нештатных ситуаций)

Подробно специфицируй сценарии реакции системы и действий операторов для всех типов сбоев перевозки:

1. **Опоздание на погрузку / срыв подачи ТС**:
   - Авто-детекция: ТС не прибыло в радиус 1 км за 30 минут до дедлайна.
   - Действия: алерт диспетчеру, автоматический запрос статуса у водителя, при подтверждении срыва — штраф перевозчику, авто-перепубликация груза с пометкой «Срочно».
2. **Поломка тягача в пути**:
   - Фиксация водителем статуса `BREAKDOWN` с гео-меткой.
   - Процесс перецепки прицепа на резервный тягач (замена VehicleId в Shipment с сохранением истории трека).
3. **ДТП / Утрата груза**:
   - Перевод в статус `EMERGENCY / CARGO_DAMAGE`.
   - Загрузка фото/видео материалов, вызов аварийного комиссара, уведомление страховой компании, инициация юридического диспута.
4. **Расхождение номенклатуры / повреждение при выгрузке**:
   - Составление электронного коммерческого акта (Act of Discrepancy) с фотофиксацией перед подписанием eCMR.
5. **Отказ грузополучателя от приемки (Failed Delivery)**:
   - Запуск процесса согласования переадресации (Re-routing) или возврата на склад отправителя (Return Workflow).

## Важные замечания для выполнения

- Схемы процессов должны быть сквозными и отвечать на вопрос: «Кто, что, в какой последовательности делает, и что происходит при сбое на каждом шаге».
