## 1. Модель авторизации

Платформа CargoPlus использует комбинированную модель **RBAC + Resource Ownership**:

1. **RBAC (Role-Based Access Control)** — роль пользователя внутри организации определяет базовые права доступа к типам операций.
2. **Resource Ownership** — проверка принадлежности ресурса: пользователь получает доступ только к ресурсам своей организации.
3. **Global Roles** — администраторы и модераторы платформы имеют расширенный доступ сверх организационных ограничений.

## 2. Организационные роли (RBAC)

### 2.1 Описание ролей

| Роль         | Описание                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------- |
| `Owner`      | Владелец организации. Полный доступ ко всем функциям, включая управление пользователями и биллингом |
| `Dispatcher` | Диспетчер. Управление грузами, заявками, маршрутами. Нет доступа к биллингу                         |
| `Accountant` | Бухгалтер. Чтение всех данных, полный доступ к финансовым документам                                |
| `Driver`     | Водитель. Доступ только к назначенным рейсам и телематике своего транспорта                         |
| `Viewer`     | Наблюдатель. Только чтение (GET-запросы)                                                            |

### 2.2 Матрица прав по ролям

| Ресурс / Действие             | Owner | Dispatcher | Accountant | Driver | Viewer |
| ----------------------------- | :---: | :--------: | :--------: | :----: | :----: |
| Грузы: создание               |  ✅   |     ✅     |     ❌     |   ❌   |   ❌   |
| Грузы: чтение                 |  ✅   |     ✅     |     ✅     |   ❌   |   ✅   |
| Грузы: редактирование         |  ✅   |     ✅     |     ❌     |   ❌   |   ❌   |
| Грузы: удаление               |  ✅   |     ✅     |     ❌     |   ❌   |   ❌   |
| Заявки перевозчиков           |  ✅   |     ✅     |     📖     |   ❌   |   📖   |
| Транспортные заказы           |  ✅   |     ✅     |     📖     |  📖*   |   📖   |
| Водители: управление          |  ✅   |     ✅     |     ❌     |   ❌   |   📖   |
| Транспорт: управление         |  ✅   |     ✅     |     ❌     |   ❌   |   📖   |
| Телематика: отправка          |  ✅   |     ❌     |     ❌     |  ✅*   |   ❌   |
| Финансовые документы          |  ✅   |     ❌     |     ✅     |   ❌   |   ❌   |
| Пользователи орг.: управление |  ✅   |     ❌     |     ❌     |   ❌   |   ❌   |
| Биллинг и подписки            |  ✅   |     ❌     |     📖     |   ❌   |   ❌   |

> 📖 = только чтение  
> \* = только собственные ресурсы (назначенные рейсы / свой транспорт)

## 3. Resource Ownership (Проверка владения ресурсом)

### 3.1 Основное правило

Доступ к ресурсу разрешён, если выполняется **хотя бы одно** из условий:

```
resource.organization_id == token.org_id
ИЛИ
token.role IN ["platform_admin", "platform_moderator"]
```

### 3.2 Алгоритм проверки доступа

```
function checkAccess(request, resource):
  1. Извлечь claims из JWT (sub, org_id, role, permissions)
  2. Если role == "platform_admin" → разрешить (пропустить шаги 3-5)
  3. Проверить RBAC: роль пользователя позволяет выполнить запрошенное действие?
     → Нет → вернуть 403 Forbidden
  4. Проверить владение: resource.organization_id == token.org_id?
     → Нет и role != "platform_moderator" → вернуть 403 Forbidden
  5. Проверить скоупы: permission in token.permissions?
     → Нет → вернуть 403 Forbidden
  6. Разрешить запрос
```

### 3.3 Пример

```
// Пользователь с org_id="org_A" пытается прочитать груз org_B:
GET /api/v1/loads/load_xyz
Authorization: Bearer <JWT с org_id="org_A">

// load_xyz.organization_id = "org_B"
// Результат: 403 Forbidden (resource.organization_id ≠ token.org_id)
```

## 4. Глобальные роли платформы

| Роль                 | Описание                | Доступ                                              |
| -------------------- | ----------------------- | --------------------------------------------------- |
| `platform_admin`     | Администратор платформы | Полный доступ к любым ресурсам любой организации    |
| `platform_moderator` | Модератор платформы     | Чтение и модерация ресурсов всех организаций        |
| `platform_support`   | Служба поддержки        | Чтение ресурсов всех организаций (только read-only) |

Глобальные роли хранятся в отдельном claim JWT (`global_role`) и никогда не пересекаются с организационными ролями.

## 5. Спецификация API Scopes

Скоупы — это детализированные разрешения, которые уточняют RBAC. Используются для API Key и OAuth2 делегирования.

### 5.1 Полный список скоупов

| Скоуп                | Описание                                      |
| -------------------- | --------------------------------------------- |
| `loads:read`         | Чтение объявлений о грузах                    |
| `loads:write`        | Создание и редактирование объявлений о грузах |
| `loads:delete`       | Удаление объявлений о грузах                  |
| `offers:read`        | Чтение предложений от перевозчиков            |
| `offers:write`       | Создание и управление предложениями           |
| `orders:manage`      | Управление транспортными заказами             |
| `orders:read`        | Чтение транспортных заказов                   |
| `drivers:manage`     | Управление водителями                         |
| `vehicles:manage`    | Управление транспортными средствами           |
| `telemetry:ingest`   | Отправка телематических данных                |
| `telemetry:read`     | Чтение телематических данных                  |
| `documents:read`     | Чтение финансовых документов                  |
| `documents:write`    | Создание финансовых документов                |
| `payments:read`      | Чтение платёжных операций                     |
| `organization:admin` | Административное управление организацией      |
| `webhooks:manage`    | Управление webhook-подписками                 |

### 5.2 Набор скоупов по роли (умолчание)

| Роль         | Скоупы по умолчанию                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------ |
| `Owner`      | Все скоупы                                                                                       |
| `Dispatcher` | `loads:read`, `loads:write`, `offers:read`, `orders:manage`, `drivers:manage`, `vehicles:manage` |
| `Accountant` | `loads:read`, `orders:read`, `documents:read`, `documents:write`, `payments:read`                |
| `Driver`     | `orders:read`, `telemetry:ingest`                                                                |
| `Viewer`     | `loads:read`, `orders:read`                                                                      |

## 6. Обработка ошибок авторизации

```json
// 403 Forbidden — недостаточно прав
{
  "type": "https://api.cargo.platform/errors/access-denied",
  "title": "Доступ запрещён",
  "status": 403,
  "detail": "Ваша роль Dispatcher не позволяет управлять биллингом организации",
  "error_code": "INSUFFICIENT_PERMISSIONS",
  "required_permission": "organization:admin"
}

// 403 Forbidden — чужой ресурс
{
  "type": "https://api.cargo.platform/errors/resource-ownership-violation",
  "title": "Доступ к ресурсу запрещён",
  "status": 403,
  "detail": "Ресурс принадлежит другой организации",
  "error_code": "RESOURCE_OWNERSHIP_VIOLATION"
}
```

> **Важно:** В ответе об ошибке `403` **никогда** не раскрывается информация о существовании ресурса, если пользователь не имеет права его видеть. В таких случаях следует использовать `404 Not Found`.
