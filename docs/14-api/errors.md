# Стандарт обработки ошибок (Error Handling)

> **Раздел:** 14-api  
> **Версия документа:** 1.0  
> **Статус:** Действующий стандарт  
> **Основание:** RFC 7807 — Problem Details for HTTP APIs  
> **Связанные документы:** [api-guidelines.md](api-guidelines.md)

---

## 1. Формат ответа об ошибке

Все ответы с HTTP статус-кодами `4xx` и `5xx` **обязаны** использовать единый формат, основанный на RFC 7807 Problem Details:

```json
{
  "type": "https://api.cargo.platform/errors/cargo-already-booked",
  "title": "Груз уже забронирован",
  "status": 409,
  "detail": "Груз с ID 123e4567-e89b-12d3-a456-426614174000 уже забронирован другим перевозчиком",
  "instance": "/api/v1/loads/123e4567-e89b-12d3-a456-426614174000/book",
  "error_code": "LOAD_ALREADY_BOOKED",
  "trace_id": "a1b2c3d4-e5f6-7890",
  "invalid_params": []
}
```

### 1.1 Описание полей

| Поле             | Тип               | Обязательное | Описание                                                               |
| ---------------- | ----------------- | :----------: | ---------------------------------------------------------------------- |
| `type`           | string (URI)      |      ✅      | Уникальная ссылка на тип ошибки с документацией                        |
| `title`          | string            |      ✅      | Краткое человекочитаемое описание типа ошибки (константа, не меняется) |
| `status`         | integer           |      ✅      | HTTP статус-код                                                        |
| `detail`         | string            |      ✅      | Подробное описание конкретного случая ошибки (может меняться)          |
| `instance`       | string (URI path) |      ✅      | Путь эндпоинта, вернувшего ошибку                                      |
| `error_code`     | string            |      ✅      | Машиночитаемый код ошибки в UPPER_SNAKE_CASE                           |
| `trace_id`       | string            |      ✅      | ID запроса для трассировки в системе мониторинга                       |
| `invalid_params` | array             |      ✅      | Массив деталей по невалидным полям (пустой если нет)                   |

### 1.2 Структура элемента `invalid_params`

```json
{
  "invalid_params": [
    {
      "field": "weight_kg",
      "message": "Вес груза должен быть больше 0",
      "rejected_value": -10
    },
    {
      "field": "destination_city",
      "message": "Поле обязательно для заполнения",
      "rejected_value": null
    }
  ]
}
```

| Поле             | Тип    | Описание                                                |
| ---------------- | ------ | ------------------------------------------------------- |
| `field`          | string | Путь к полю (поддерживает dot-notation: `address.city`) |
| `message`        | string | Описание ошибки валидации                               |
| `rejected_value` | any    | Значение, которое было отклонено                        |

## 2. Реестр кодов ошибок

### 2.1 Ошибки аутентификации и авторизации (401, 403)

| `error_code`                   | HTTP | Описание                                                |
| ------------------------------ | ---- | ------------------------------------------------------- |
| `MISSING_AUTHENTICATION`       | 401  | Заголовок аутентификации отсутствует                    |
| `TOKEN_EXPIRED`                | 401  | Access Token истёк                                      |
| `TOKEN_INVALID`                | 401  | Токен повреждён или подписан неверным ключом            |
| `TOKEN_REVOKED`                | 401  | Токен был отозван (logout или компрометация)            |
| `REFRESH_TOKEN_EXPIRED`        | 401  | Refresh Token истёк, требуется повторная аутентификация |
| `API_KEY_INVALID`              | 401  | API Key не найден или недействителен                    |
| `API_KEY_EXPIRED`              | 401  | API Key истёк                                           |
| `INSUFFICIENT_PERMISSIONS`     | 403  | Роль не позволяет выполнить операцию                    |
| `RESOURCE_OWNERSHIP_VIOLATION` | 403  | Ресурс принадлежит другой организации                   |
| `SCOPE_MISSING`                | 403  | У токена нет необходимого скоупа                        |

### 2.2 Ошибки валидации (400, 422)

| `error_code`                | HTTP | Описание                                      |
| --------------------------- | ---- | --------------------------------------------- |
| `INVALID_REQUEST_BODY`      | 400  | Тело запроса не является валидным JSON        |
| `MISSING_REQUIRED_FIELD`    | 400  | Отсутствует обязательное поле                 |
| `FIELD_VALIDATION_ERROR`    | 422  | Одно или несколько полей не прошли валидацию  |
| `MISSING_IDEMPOTENCY_KEY`   | 400  | Заголовок Idempotency-Key обязателен          |
| `INVALID_UUID_FORMAT`       | 400  | Невалидный формат UUID                        |
| `INVALID_DATE_FORMAT`       | 400  | Дата не соответствует формату ISO 8601        |
| `INVALID_SORT_FIELD`        | 400  | Запрошенное поле сортировки не поддерживается |
| `INVALID_PAGINATION_CURSOR` | 400  | Курсор пагинации повреждён или истёк          |

### 2.3 Бизнес-логика (409, 422)

| `error_code`                       | HTTP | Описание                                                |
| ---------------------------------- | ---- | ------------------------------------------------------- |
| `LOAD_ALREADY_BOOKED`              | 409  | Груз уже забронирован другим перевозчиком               |
| `LOAD_NOT_PUBLISHED`               | 422  | Груз не опубликован и недоступен для бронирования       |
| `OFFER_EXPIRED`                    | 422  | Предложение перевозчика истекло                         |
| `ORDER_CANNOT_BE_CANCELLED`        | 422  | Статус заказа не позволяет его отменить                 |
| `DUPLICATE_RESOURCE`               | 409  | Ресурс с такими данными уже существует                  |
| `IDEMPOTENCY_KEY_IN_USE`           | 409  | Запрос с данным ключом ещё обрабатывается               |
| `IDEMPOTENCY_KEY_PAYLOAD_MISMATCH` | 422  | Тело запроса не совпадает с первоначальным              |
| `INSUFFICIENT_BALANCE`             | 422  | Недостаточно средств на счёте для выполнения операции   |
| `ORGANIZATION_SUSPENDED`           | 403  | Организация заблокирована на платформе                  |
| `VEHICLE_CAPACITY_EXCEEDED`        | 422  | Вес или объём груза превышает допустимый для транспорта |

### 2.4 Ошибки ресурсов (404, 410)

| `error_code`         | HTTP | Описание                     |
| -------------------- | ---- | ---------------------------- |
| `RESOURCE_NOT_FOUND` | 404  | Запрошенный ресурс не найден |
| `API_VERSION_SUNSET` | 410  | Версия API отключена         |

### 2.5 Системные ошибки (429, 500, 503)

| `error_code`            | HTTP | Описание                               |
| ----------------------- | ---- | -------------------------------------- |
| `RATE_LIMIT_EXCEEDED`   | 429  | Превышен лимит частоты запросов        |
| `INTERNAL_SERVER_ERROR` | 500  | Непредвиденная внутренняя ошибка       |
| `SERVICE_UNAVAILABLE`   | 503  | Сервис временно недоступен             |
| `UPSTREAM_TIMEOUT`      | 503  | Таймаут ответа от вышестоящего сервиса |

## 3. Примеры ответов об ошибках

### 3.1 Ошибка валидации (422)

```json
{
  "type": "https://api.cargo.platform/errors/field-validation-error",
  "title": "Ошибка валидации полей",
  "status": 422,
  "detail": "2 поля не прошли валидацию. Исправьте значения и повторите запрос.",
  "instance": "/api/v1/loads",
  "error_code": "FIELD_VALIDATION_ERROR",
  "trace_id": "b2c3d4e5-f6a7-8901",
  "invalid_params": [
    {
      "field": "weight_kg",
      "message": "Вес груза должен быть положительным числом",
      "rejected_value": -10
    },
    {
      "field": "available_from",
      "message": "Дата готовности не может быть в прошлом",
      "rejected_value": "2020-01-01T00:00:00Z"
    }
  ]
}
```

### 3.2 Конфликт состояния (409)

```json
{
  "type": "https://api.cargo.platform/errors/load-already-booked",
  "title": "Груз уже забронирован",
  "status": 409,
  "detail": "Груз с ID 123e4567-e89b-12d3-a456-426614174000 уже забронирован другим перевозчиком в 10:28 UTC",
  "instance": "/api/v1/loads/123e4567-e89b-12d3-a456-426614174000/book",
  "error_code": "LOAD_ALREADY_BOOKED",
  "trace_id": "a1b2c3d4-e5f6-7890",
  "invalid_params": []
}
```

### 3.3 Превышение лимита (429)

```json
{
  "type": "https://api.cargo.platform/errors/rate-limit-exceeded",
  "title": "Превышен лимит запросов",
  "status": 429,
  "detail": "Вы превысили лимит 600 запросов в минуту. Повторите запрос через 23 секунды.",
  "instance": "/api/v1/loads",
  "error_code": "RATE_LIMIT_EXCEEDED",
  "trace_id": "c3d4e5f6-a7b8-9012",
  "invalid_params": [],
  "retry_after_seconds": 23
}
```

### 3.4 Внутренняя ошибка сервера (500)

```json
{
  "type": "https://api.cargo.platform/errors/internal-server-error",
  "title": "Внутренняя ошибка сервера",
  "status": 500,
  "detail": "Произошла непредвиденная ошибка. Мы уже работаем над её устранением. Используйте trace_id при обращении в поддержку.",
  "instance": "/api/v1/transport-orders",
  "error_code": "INTERNAL_SERVER_ERROR",
  "trace_id": "d4e5f6a7-b8c9-0123",
  "invalid_params": []
}
```

> **Важно:** В ответах `500` **никогда** не раскрываются детали внутренней реализации (stack traces, SQL-запросы, пути файлов).

## 4. Правила реализации

### 4.1 Content-Type для ошибок

```
Content-Type: application/problem+json; charset=utf-8
```

### 4.2 Обязательная документация типов ошибок

Каждый URI в поле `type` должен быть валидным URL, доступным для разработчиков:

- `https://api.cargo.platform/errors/{error-slug}` ведёт на страницу документации с примером и рекомендациями по исправлению.

### 4.3 Безопасность в ошибках

- Никогда не включать в ответ: стек вызовов, SQL-запросы, внутренние IP, пути к файлам.
- При `404` для ресурсов, видимость которых зависит от прав — возвращать `404` (не `403`), чтобы не раскрывать существование ресурса.
