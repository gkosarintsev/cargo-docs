# Email — Транзакционные и триггерные письма

## Назначение

Email-канал используется для доставки транзакционных уведомлений, требующих детального форматирования: подтверждений сделок, счетов, отчётов и сводок. Email не является основным каналом оперативных уведомлений — для этого предназначены Push и In-App.

## Инфраструктура отправки

### Провайдеры

| Провайдер     | Назначение                                | Регион      |
| ------------- | ----------------------------------------- | ----------- |
| Postmark      | Транзакционные письма (высокий приоритет) | EU / Global |
| AWS SES       | Массовые рассылки (дайджесты, маркетинг)  | EU / Global |
| VK Cloud Mail | Резервный провайдер для пользователей RU  | RU          |

Выбор провайдера определяется типом письма и регионом пользователя. Переключение между провайдерами — автоматическое через Circuit Breaker при ошибках доставки.

### DNS-аутентификация (Anti-Spam)

```text
SPF:   v=spf1 include:_spf.postmark.com include:amazonses.com -all
DKIM:  Selector: pm, 2048-bit RSA key, ротация ежегодно
DMARC: v=DMARC1; p=quarantine; rua=mailto:dmarc@platform.example; pct=100
```

Все исходящие письма подписываются DKIM. Домен-отправитель: `noreply@platform.example`.

## Шаблонизация

### Технологический стек

- **MJML** — языковой слой для написания адаптивных email-шаблонов.
- **Handlebars** — движок шаблонов для подстановки переменных.
- MJML компилируется в HTML при деплое; переменные подставляются в runtime.

### Структура шаблона

```
templates/
  email/
    auth/
      welcome.ru.mjml
      welcome.en.mjml
      password_reset.ru.mjml
    operational/
      offer_accepted.ru.mjml
      driver_assigned.ru.mjml
      delivery_completed.ru.mjml
    financial/
      invoice_issued.ru.mjml
      payment_received.ru.mjml
      payment_overdue.ru.mjml
    system/
      account_blocked.ru.mjml
      maintenance_notice.ru.mjml
```

```handlebars
{{user.name}}
```

## Обработка bounce и жалоб

### Типы bounce

- **Hard bounce** (недоступный адрес): email немедленно помечается как невалидный в профиле пользователя, дальнейшие отправки блокируются.
- **Soft bounce** (временная недоступность): повтор через 5 мин, 30 мин, 2 часа. После 3 неудачных попыток — статус `FAILED`.

### Обработка Complaint (спам-жалоба)

Postmark / SES уведомляет через Webhook при получении жалобы пользователя. Платформа:

1. Немедленно отписывает пользователя от маркетинговых рассылок.
2. Переводит транзакционные письма в режим «только критические» (OTP, блокировка аккаунта).
3. Логирует событие для анализа репутации домена.

## Метрики доставки

| Метрика                    | Целевое значение |
| -------------------------- | ---------------- |
| Delivery Rate              | > 98%            |
| Open Rate (транзакционные) | > 40%            |
| Bounce Rate                | < 2%             |
| Spam Complaint Rate        | < 0.1%           |

Метрики собираются через Webhook-события провайдеров и экспортируются в ClickHouse для анализа.
