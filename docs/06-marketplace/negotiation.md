# Сессии переговоров (Negotiation)

Для обеспечения высокой скорости контрактации грузовладельцам предоставляется инструмент параллельных торгов.

## 1. Модель параллельных торгов

Грузовладелец не ограничен переговорами только с одним потенциальным исполнителем. Он может вести торги конкурентно.

- **Параллельные сессии**: По одному выставленному грузу грузовладелец может одновременно вести переговоры с несколькими (например, с тремя) независимыми перевозчиками.
- **Конкуренция**: Перевозчики не видят ставки друг друга, но могут получать статусные индикаторы («На этот груз претендуют еще N перевозчиков»), что стимулирует их предлагать более конкурентные условия.
- **Автоматическое разрешение конфликтов**: Как только грузовладелец акцептует предложение одного из перевозчиков (или перевозчик акцептует предложение грузовладельца), сделка считается заключенной.
  - В этот же момент система **автоматически** закрывает все остальные открытые сессии торгов по данному грузу.
  - Оставшимся участникам рассылаются уведомления, а их сессии переводятся в терминальный статус `SUPERSEDED_AND_CLOSED` (перекрыто другой сделкой).

## 2. Встроенный контекстный чат

Для обсуждения деталей, не покрываемых жесткими атрибутами ставки (например, точных координат заезда на склад, особенностей упаковки), в систему интегрирован контекстный чат.

- **Привязка к сессии**: Сообщения чата жестко привязаны к конкретной сессии торга (`negotiation_id`).
- **Сквозной контекст**: В интерфейсе чата всегда отображается карточка груза и текущая обсуждаемая ставка, что исключает путаницу при одновременном ведении нескольких переговоров.
- **Арбитраж**: Логирование чата внутри платформы позволяет службе поддержки использовать историю переписки для разрешения споров (арбитража) между сторонами в случае конфликтных ситуаций на погрузке/выгрузке.
