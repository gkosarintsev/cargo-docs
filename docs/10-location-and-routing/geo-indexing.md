# Гео-индексирование и пространственный поиск

## Пространственные индексы: Сравнительный анализ

Для эффективного поиска по координатам (например, "найти все свободные фуры в радиусе 100 км от склада") классические B-Tree индексы не подходят. В платформе используется гибридный подход к гео-индексированию. Ниже представлен анализ рассматриваемых технологий (PostGIS, H3, Geohash, OpenSearch).

### 1. PostGIS (PostgreSQL)

- **Механизм**: Расширение PostgreSQL, использующее R-Tree (через GiST индексы) для двумерных пространственных данных.
- **Преимущества**: Поддерживает сложную геометрию (полигоны, мультиполигоны). Идеально для точных проверок пересечений (`ST_Intersects`), вхождения точки в полигон (`ST_Contains`), точного расчета расстояний с учетом кривизны земли.
- **Недостатки**: Тяжеловесные запросы. Не подходит для высокочастотных обновлений координат (тысячи TPS).

### 2. Uber H3 (Hexagonal Hierarchical Spatial Index)

- **Механизм**: Разбивает поверхность Земли на иерархическую сетку из шестиугольников. Координата преобразуется в 64-битный идентификатор (H3 Index).
- **Преимущества**: Соседние гексагоны всегда находятся на равном расстоянии. Идеально для динамического агрегирования плотности (Heatmaps — зоны высокого спроса), расчета Surge Pricing. Поиск машин в радиусе выполняется как поиск соседних гексагонов ($K$-колец / k-ring) — это простые операции с графами (хешами), исключающие дорогие тригонометрические вычисления.
- **Недостатки**: Это аппроксимация; границы шестиугольников не совпадают с реальными дорогами или геозонами.

### 3. Geohash

- **Механизм**: Z-order curve (Кривая Мортона). Кодирует координаты в строку (префикс). Чем больше совпадающий префикс у двух строк, тем ближе точки.
- **Преимущества**: Префиксный строковый индекс крайне удобен для хранения в in-memory хранилищах (Redis `GEOADD`/`GEORADIUS`), шардирования и быстрых префиксных поисков.
- **Недостатки**: Проблема границ (точки по разные стороны границы деления сетки могут иметь разный префикс, находясь рядом физически).

### 4. OpenSearch (Elasticsearch) Geo

- **Механизм**: Типы `geo_point` / `geo_shape` под капотом используют BKD-деревья.
- **Преимущества**: Оптимизированы для одновременной гео-фильтрации и текстового/фасетного поиска. Например: "найти машины в радиусе 50км (geo), которые являются рефрижераторами (facet) и имеют рейтинг > 4.5 (range)".
- **Недостатки**: Обновление документов дорогое (требует реиндексации Lucene сегментов), не подходит для realtime трекинга.

## Итоговая матрица использования (Архитектурное решение)

Мы не выбираем одну технологию, а используем гибридный подход, распределяя задачи по оптимальным хранилищам:

| Технология          | Сценарий использования в платформе                                                                                                             | Почему именно этот выбор                                                                                                                      |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- |
| **Redis (Geohash)** | **Realtime Tracking**: Хранение текущих позиций машин. Быстрый поиск машин в заданном радиусе (Search Radius) для диспетчера.                  | Поддержка сверхвысокой частоты записи (десятки тысяч UPS). Встроенные команды `GEOADD`/`GEOSEARCH`.                                           |
| **Uber H3**         | **Аналитика и Матчинг**: Построение тепловых карт (спрос/предложение). Агрегация машин по гексагонам резолюции 4-6 для быстрого батч-матчинга. | Быстрое $O(1)$ объединение в бакеты. Эффективный поиск смежных зон (k-ring) без расчета дистанций по сфере.                                   |
| **PostGIS**         | **Геозоны (Geofencing)**: Хранение точных полигонов складов, геозон зон запрета, административных границ.                                      | Необходима максимальная точность полигонов и функции проверки `ST_Contains` для генерации событий въезда/выезда. Редкие обновления полигонов. |
| **OpenSearch**      | **Поиск грузов и заявок**: Фасетный поиск грузов на бирже с учетом гео-bounding box (область видимости карты).                                 | Необходимость комбинировать гео-поиск с полнотекстовым поиском и сложной фильтрацией по десяткам атрибутов.                                   |
