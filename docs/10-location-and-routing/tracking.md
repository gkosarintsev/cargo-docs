# Архитектура отображения и хранения трекинга

## Обзор

Хранение телеметрии требует компромисса между скоростью доступа (показать машинку на карте прямо сейчас) и объемом данных (хранить историю за 3 года для аналитики). В системе применяется паттерн Polyglot Persistence — разделение данных по типам хранилищ в зависимости от "температуры" данных.

## Разделение видов данных

### 1. Current State (Горячие данные)

- **Что это**: Самая последняя известная координата ТС, текущая скорость, азимут (направление), статус батареи, статус GPS-сигнала.
- **Хранилище**: **Redis**.
- **Структура**: Использование `GEOADD` для координат (поиск по радиусу) и обычных ключей/Hash (например, `vehicle:state:{id}`) для метаданных.
- **Жизненный цикл**: Короткий TTL (например, 24 часа). Если машина не выходит на связь сутки, она пропадает из "горячего" слоя.
- **Потребители**: API диспетчеров (быстрая отрисовка всех машин на карте), механизмы матчинга (поиск машин рядом с грузом).

### 2. Event History (Событийные данные)

- **Что это**: Важные бизнес-факты, извлеченные из потока сырых координат.
  - Срабатывания геозон (Geofence Events): Въезд на территорию склада (`ENTER`), выезд (`EXIT`).
  - События телематики: Превышение скорости (`OVERSPEED`), резкое торможение, открытие дверей прицепа.
  - Изменения ETA или статуса рейса.
- **Хранилище**: **PostgreSQL** (в схеме основного монолита или сервиса трекинга).
- **Структура**: Реляционные таблицы событий с привязкой к ID рейса (Trip/Load ID).
- **Потребители**: Диспетчеры (история рейса), биллинг (начисление штрафов за простой), клиенты (отчеты о прибытии).

### 3. Analytical Time Series (Исторический трек)

- **Что это**: Весь сырой массив переданных точек (миллионы записей в день). Траектория движения (Track) за весь период работы.
- **Хранилище**: **TimescaleDB** (расширение PostgreSQL для временных рядов) или **ClickHouse**.
- **Особенности хранения**:
  - Высокая степень сжатия колоночных данных (ClickHouse) или чанков (TimescaleDB).
  - Retention Policy: сырые точки хранятся 3-6 месяцев (для разбора инцидентов), после чего агрегируются или удаляются.
- **Потребители**: Аналитики (построение тепловых карт H3), ML-модели (обучение модели расчета ETA), функционал "воспроизвести трек рейса за 14 марта" (Playback).

## Выдача данных (Delivery)

Для отображения движущихся машин на карте в реальном времени:

1. Клиент (Web UI диспетчера) открывает **WebSocket** или **Server-Sent Events (SSE)** соединение с Edge Gateway.
2. Подписывается на конкретные ТС или на Bounding Box видимой области карты.
3. Изменения, проходящие через Stream Processor, пушатся напрямую клиенту (pub/sub), минимизируя HTTP polling.
