# Архитектура управления документами

## Разделение хранения

### Метаданные в PostgreSQL

Все метаданные документов хранятся в реляционной базе данных в таблице `documents`:

| Поле          | Тип         | Описание                                                    |
| ------------- | ----------- | ----------------------------------------------------------- |
| `document_id` | UUID        | Уникальный идентификатор документа                          |
| `entity_type` | ENUM        | Тип связанной сущности: `Order`, `Shipment`, `Organization` |
| `entity_id`   | UUID        | Идентификатор связанной сущности                            |
| `doc_type`    | ENUM        | Тип документа (CMR, ЭТрН, УПД и т.д.)                       |
| `version`     | INTEGER     | Версия документа (начиная с 1)                              |
| `mime_type`   | VARCHAR     | MIME-тип файла (application/pdf, image/jpeg и т.д.)         |
| `file_size`   | BIGINT      | Размер файла в байтах                                       |
| `sha256_hash` | CHAR(64)    | Хэш-сумма SHA-256 содержимого файла                         |
| `s3_key`      | VARCHAR     | Путь к файлу в S3 Object Storage                            |
| `created_by`  | UUID        | Идентификатор пользователя, создавшего документ             |
| `created_at`  | TIMESTAMPTZ | Дата и время создания                                       |
| `status`      | ENUM        | Статус документа (DRAFT, SIGNED, ARCHIVED и т.д.)           |

### Файлы в S3 Object Storage

Бинарное содержимое документов хранится в S3-совместимом объектном хранилище со следующими характеристиками:

- **WORM (Write Once, Read Many)**: неизменяемое хранение — загруженный файл не может быть изменён или удалён до истечения установленного срока хранения (S3 Object Lock).
- **SSE-S3**: шифрование на стороне сервера — все файлы хранятся в зашифрованном виде с управляемыми ключами шифрования.
- **Pre-signed URLs**: для скачивания и просмотра генерируются короткоживущие подписанные ссылки (время жизни — 15 минут по умолчанию). Прямой публичный доступ к бакету отсутствует.
- **Версионирование бакета**: включено для защиты от случайного удаления.

### Структура ключей S3

```
s3://<bucket>/
  documents/
    <entity_type>/
      <entity_id>/
        <doc_type>/
          <document_id>_v<version>.<ext>
```

Пример:

```
s3://cargo-docs-prod/documents/shipment/a1b2c3.../cmr/f4e5d6..._v1.pdf
```

## Пакет документов (DocumentPackage)

`DocumentPackage` — агрегированный объект, объединяющий все документы, относящиеся к конкретной перевозке (`Shipment`), в единый логический пакет.

### Возможности

- **Проверка комплектности**: система автоматически проверяет наличие обязательных документов для данного типа перевозки (внутренняя, международная, ADR) перед закрытием перевозки.
- **Экспорт в ZIP-архив**: по запросу пользователя или автоматически при закрытии перевозки формируется ZIP-архив со всеми документами пакета и машиночитаемым манифестом (`manifest.json`).
- **Манифест архива**: содержит список файлов с их хэшами SHA-256 для верификации целостности после передачи.

### Обязательные документы по типу перевозки

| Тип перевозки        | Обязательные документы                                |
| -------------------- | ----------------------------------------------------- |
| Внутренняя (FTL/LTL) | ТТН (1-Т) или ЭТрН, Путевой лист, Договор-заявка      |
| Международная        | CMR или eCMR, Инвойс, Упаковочный лист, Сертификаты   |
| ADR (опасные грузы)  | CMR, Удостоверение ДОПОГ водителя, Аварийная карточка |

## Интеграция с другими подсистемами

- **Сервис уведомлений**: при смене статуса документа отправляются уведомления ответственным участникам.
- **Финансовый модуль**: УПД и акты сдачи-приемки автоматически передаются в модуль взаиморасчётов после подписания.
- **Модуль ЭДО**: подписанные ЭТрН и eCMR передаются операторам ИС ЭПД.
