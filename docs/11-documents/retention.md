# Политика архивного хранения и уничтожения документов

## Сроки хранения

Сроки хранения документов определяются действующим законодательством РФ:

| Категория документов                               | Нормативный акт                                 | Срок хранения                 |
| -------------------------------------------------- | ----------------------------------------------- | ----------------------------- |
| Первичные бухгалтерские документы (УПД, акты, ТТН) | 402-ФЗ «О бухгалтерском учёте», ст. 29          | **5 лет**                     |
| Счета-фактуры                                      | НК РФ, ст. 169                                  | **5 лет**                     |
| Договоры-заявки, экспедиторские расписки           | Гражданское законодательство (исковая давность) | **3 года**                    |
| ЭТрН и CMR                                         | Приказ Минтранса, Конвенция КДПГ                | **5 лет**                     |
| Путевые листы                                      | Приказ Минтранса № 390                          | **5 лет**                     |
| Фотоматериалы PoD (сырые фото)                     | Внутренняя политика                             | **1 год**                     |
| Документы по претензиям                            | Гражданское законодательство                    | **3 года** с момента закрытия |
| Аудит-логи доступа                                 | 149-ФЗ, внутренняя политика                     | **3 года**                    |

## Автоматическая ротация в холодные уровни хранения

Для оптимизации затрат на хранение применяется многоуровневая архитектура S3 с автоматическим переносом объектов между уровнями через **S3 Lifecycle Rules**:

```
Загрузка (S3 Standard)
    │
    │ 30 дней
    ▼
S3 Standard-IA (Infrequent Access)
    │  — Для документов, к которым редко обращаются
    │  — Стоимость хранения ниже, чем Standard
    │
    │ 90 дней с момента загрузки
    ▼
S3 Glacier Instant Retrieval
    │  — Для документов старше 3 месяцев
    │  — Восстановление за миллисекунды
    │
    │ 365 дней с момента загрузки (1 год)
    ▼
S3 Glacier Deep Archive
    │  — Долгосрочный архив (бухгалтерские первичные документы)
    │  — Восстановление за 12–48 часов
    │  — Минимальная стоимость хранения
    │
    │ По истечении срока хранения
    ▼
Автоматическое удаление (Expiration rule)
```

### Конфигурация Lifecycle Rules (пример для бухгалтерских документов)

```xml
<LifecycleConfiguration>
  <Rule>
    <ID>accounting-docs-lifecycle</ID>
    <Filter><Prefix>documents/accounting/</Prefix></Filter>
    <Status>Enabled</Status>
    <Transition>
      <Days>30</Days>
      <StorageClass>STANDARD_IA</StorageClass>
    </Transition>
    <Transition>
      <Days>90</Days>
      <StorageClass>GLACIER_IR</StorageClass>
    </Transition>
    <Transition>
      <Days>365</Days>
      <StorageClass>DEEP_ARCHIVE</StorageClass>
    </Transition>
    <Expiration>
      <Days>1825</Days> <!-- 5 лет -->
    </Expiration>
  </Rule>
</LifecycleConfiguration>
```

## Удаление персональных данных (GDPR / 152-ФЗ)

### Принцип «права на забвение»

По запросу субъекта персональных данных система должна удалить (или обезличить) его персональные данные. Однако это вступает в противоречие с требованиями бухгалтерского законодательства об обязательном сохранении первичных документов.

### Решение: selective anonymization (избирательная обезличивание)

Применяется следующий подход:

```
Запрос на удаление ПД от субъекта
    │
    ▼
Классификация данных субъекта:
    │
    ├── Данные в первичных бухгалтерских документах (ТТН, УПД, акты)?
    │     └── НЕ удаляются (требование 402-ФЗ)
    │           └── Статус помечается как "deletion_requested" в аудит-логе
    │
    ├── Данные в профиле пользователя и CRM?
    │     └── УДАЛЯЮТСЯ / ОБЕЗЛИЧИВАЮТСЯ в течение 30 дней
    │
    ├── Сырые фото PoD с лицами?
    │     └── УДАЛЯЮТСЯ немедленно (если истёк срок 1 год) или помечаются на удаление
    │
    └── Аудит-логи с IP и user-agent?
          └── IP ОБЕЗЛИЧИВАЕТСЯ (замена на XXX.XXX.XXX.XXX)
```

### Процедура обработки запроса

1. Субъект подаёт запрос через личный кабинет или email оператора.
2. Система создаёт тикет `DataDeletionRequest` со статусом `PENDING`.
3. В течение **30 дней** (согласно 152-ФЗ и GDPR) система:
   - Обезличивает профильные данные (ФИО → «Удалённый пользователь», телефон/email → null).
   - Удаляет сырые фото с персональными данными (лица, документы), не относящиеся к первичным бухгалтерским.
   - Помечает записи в аудит-логе — IP-адрес маскируется.
4. Факт выполнения запроса фиксируется в `DataDeletionRequest` со статусом `COMPLETED`.
5. Уведомление субъекту об исполнении запроса.

### Что НЕ удаляется при запросе GDPR/152-ФЗ

- Первичные бухгалтерские документы (ТТН, УПД, акты сдачи-приемки).
- Счета-фактуры и ЭТрН.
- Данные о финансовых транзакциях.
- Аудит-логи подписания юридически значимых документов.

Это соответствует позиции Роскомнадзора и EDPB (European Data Protection Board): обязательные требования законодательства о хранении данных имеют приоритет над правом на забвение.

## Мониторинг и алерты

- **Ежедневный отчёт**: количество документов по уровням хранения, объём данных.
- **Алерт**: если документ с истёкшим сроком хранения не был удалён в течение 7 дней после дедлайна.
- **Алерт**: если запрос на удаление ПД не был обработан в течение 25 дней (резерв 5 дней до истечения 30-дневного срока).
