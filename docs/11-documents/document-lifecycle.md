# Жизненный цикл и версионирование документов

## Статусы документа

Каждый документ в системе проходит через определённые статусы:

```
DRAFT
  │
  ▼
GENERATED ──────────────────────────────────────────────┐
  │                                                      │
  ▼                                                      │
PENDING_SIGNATURE                                        │
  │                                                      │
  ▼                                                      │
PARTIALLY_SIGNED (если требуется несколько подписей)     │
  │                                                      │
  ▼                                                      │
FULLY_SIGNED                                             │
  │                          ┌─────────────────────────┘
  ▼                          ▼
ARCHIVED              REJECTED (отклонён любой из подписантов)
```

### Описание статусов

| Статус              | Описание                                         | Переходы                                         |
| ------------------- | ------------------------------------------------ | ------------------------------------------------ |
| `DRAFT`             | Черновик документа, не финализирован             | → `GENERATED`                                    |
| `GENERATED`         | Документ сформирован, готов к подписанию         | → `PENDING_SIGNATURE`, `REJECTED`                |
| `PENDING_SIGNATURE` | Ожидает подписания (отправлен подписантам)       | → `PARTIALLY_SIGNED`, `FULLY_SIGNED`, `REJECTED` |
| `PARTIALLY_SIGNED`  | Подписан частью подписантов (актуально для ЭТрН) | → `FULLY_SIGNED`, `REJECTED`                     |
| `FULLY_SIGNED`      | Подписан всеми необходимыми сторонами            | → `ARCHIVED`                                     |
| `REJECTED`          | Отклонён одним из подписантов                    | → `DRAFT` (пересоздание)                         |
| `ARCHIVED`          | Помещён в архив по истечении активного периода   | (терминальный)                                   |

## Неизменяемость и версионирование

Система обеспечивает **полную неизменяемость** каждой версии документа:

- Загруженный файл никогда не перезаписывается в S3 (WORM).
- При необходимости внесения правок (обнаружена ошибка, изменились данные) **создаётся новая версия** документа — новая сущность `DocumentVersion`.

### Модель версионирования

```
Document (document_id: uuid, current_version: 3)
  │
  ├── DocumentVersion (version: 1, status: REJECTED, s3_key: .../v1.pdf)
  │     └── created_at: 2026-01-10T09:00Z, rejected_at: 2026-01-10T14:00Z
  │
  ├── DocumentVersion (version: 2, status: REJECTED, s3_key: .../v2.pdf)
  │     └── created_at: 2026-01-10T15:00Z, rejected_at: 2026-01-11T08:00Z
  │
  └── DocumentVersion (version: 3, status: FULLY_SIGNED, s3_key: .../v3.pdf)
        └── created_at: 2026-01-11T09:00Z, signed_at: 2026-01-11T12:00Z
```

- Каждая версия хранит ссылку `previous_version_id` на предыдущую.
- Старые версии не удаляются — доступны для аудита.

## Аудит-лог

Все действия с документом фиксируются в таблице `document_audit_log`. Принцип: **никаких DELETE, только INSERT**.

### Структура записи аудит-лога

| Поле           | Тип         | Описание                                                   |
| -------------- | ----------- | ---------------------------------------------------------- |
| `log_id`       | UUID        | Идентификатор записи                                       |
| `document_id`  | UUID        | Идентификатор документа                                    |
| `version`      | INTEGER     | Версия документа                                           |
| `action`       | ENUM        | Тип действия                                               |
| `performed_by` | UUID        | Идентификатор пользователя                                 |
| `performed_at` | TIMESTAMPTZ | Точное время действия                                      |
| `ip_address`   | INET        | IP-адрес, с которого выполнено действие                    |
| `user_agent`   | TEXT        | User-Agent браузера / приложения                           |
| `metadata`     | JSONB       | Дополнительные данные (старый статус, новый статус и т.д.) |

### Фиксируемые действия

| Действие             | Описание                            |
| -------------------- | ----------------------------------- |
| `CREATED`            | Документ создан                     |
| `VIEWED`             | Документ открыт для просмотра       |
| `DOWNLOADED`         | Файл скачан                         |
| `SENT_FOR_SIGNATURE` | Документ отправлен на подписание    |
| `SIGNED`             | Документ подписан пользователем     |
| `REJECTED`           | Документ отклонён                   |
| `ARCHIVED`           | Документ архивирован                |
| `DELETION_REQUESTED` | Запрошено удаление ПД (GDPR/152-ФЗ) |

## Уведомления

При смене статуса документа система отправляет уведомления через сервис нотификаций:

- Email-уведомление ответственным лицам.
- Push-уведомление в мобильное приложение водителя (при смене статуса ЭТрН).
- Webhook-вызов в интегрированные внешние системы (ERP, ТМС клиента).
