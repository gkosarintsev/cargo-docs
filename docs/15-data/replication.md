# Репликация и масштабирование БД

## Топология репликации PostgreSQL
- **Primary Node (Read-Write)** + 2 Синхронные/Полусинхронные реплики для обеспечения высокой доступности (High Availability) через Patroni/etcd.
- **2 Асинхронные Read-Replicas** для тяжелых отчетов, выгрузок и чтения списков данных без нагрузки на Primary.

## Маршрутизация запросов (Read/Write Splitting)
- Используются пулеры соединений (PgBouncer или Odyssey).
- **Принцип маршрутизации**:
  - Мутирующие запросы (INSERT, UPDATE, DELETE) и критическое чтение (Read-Your-Writes) идут строго на **Primary**.
  - Фильтрация каталогов, поиск и пагинация — на **Read Replicas** с обязательным контролем задержки репликации (Replication Lag < 100ms).
