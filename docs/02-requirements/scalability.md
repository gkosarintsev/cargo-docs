# Масштабируемость (Scalability)

Этот документ описывает модель нагрузки логистической платформы и подходы к масштабированию различных подсистем для обеспечения устойчивой работы в условиях растущего трафика и пиковых нагрузок.

## 1. Модель нагрузки по трем профилям

Система должна быть спроектирована с учетом трех основных профилей нагрузки:

- **Normal (Базовый рабочий день):** Стандартная нагрузка в рабочие часы без внешних событий.
- **Peak (Конец месяца / сезонный пик):** Ожидаемые пики активности, характерные для логистической отрасли.
- **Extreme / Stress (Промо-кампании, форс-мажор):** Краткосрочные всплески нагрузки (х2-х5 от Normal), например, при масштабных маркетинговых акциях или резком притоке пользователей из-за отключения конкурентов.

### Таблица метрик профилей нагрузки

| Метрика                                                              | Normal                    | Peak                       | Extreme / Stress        |
| :------------------------------------------------------------------- | :------------------------ | :------------------------- | :---------------------- |

## 2. Оси масштабирования по подсистемам (Scaling Dimensions)

Для обеспечения целевых показателей применяются следующие стратегии масштабирования:

### API Gateway & Stateless Services

- **Горизонтальное автомасштабирование (HPA):** Все stateless микросервисы (бизнес-логика, BFF) развертываются в Kubernetes и автоматически масштабируются на основе метрик (CPU, RAM, RPS).

### Поисковый кластер (Marketplace Search)

- **Технологии:** OpenSearch / Elasticsearch.
- **Стратегия:** Индексы шардируются (Sharding) по геолокациям или временным диапазонам. Используется репликация (Replication) для обеспечения высокой доступности и распределения Read-нагрузки.

### GPS Ingestion Pipeline

- **Технологии:** Kafka, Ingress Gateways.
- **Стратегия:** Топики Kafka партиционируются (Partitioning) по ключам `device_id` или `vehicle_id`, что позволяет горизонтально масштабировать консьюмеров без потери гарантий порядка обработки данных.

### Транзакционные БД (Core Database)

- **Технологии:** PostgreSQL.
- **Стратегия:** Использование Read Replicas для распределения нагрузки на чтение. Вертикальное масштабирование инстансов БД, использование Connection Pooling (PgBouncer). Будущее партиционирование (Partitioning/Sharding) таблиц с высокой интенсивностью записи по тенантам или регионам.

### TimeSeries / GPS History

- **Технологии:** ClickHouse или специализированная TSDB.
- **Стратегия:** Горизонтальное шардирование кластера. Строгие политики удержания данных (Retention Policies): горячие данные на NVMe дисках, исторические данные сжимаются и перемещаются в холодное хранилище (S3 Object Storage).

### Мессенджер и WebSocket-шлюзы

- **Технологии:** WebSocket Servers, Redis.
- **Стратегия:** Балансировка соединений, поддержание привязки сессий (Sticky Sessions). Распределение сообщений (Broadcast) между нодами WebSocket осуществляется через Redis Pub/Sub.
