# Аварийное восстановление (Disaster Recovery)

План аварийного восстановления описывает стратегию восстановления платформы в случае критических сбоев или региональных катастроф.

## 1. Классификация данных

Для оптимизации резервирования данные разделены на три уровня:

- **Critical (Критичные):** Заказы, финансы, профили пользователей, юридические документы. Потеря недопустима.
- **Recoverable (Восстанавливаемые):** Индексы поиска. Данные могут быть перестроены (re-indexed) из Critical баз.
- **Ephemeral (Временные):** Кэш, временные сессии, краткосрочная сырая история GPS. Данные могут быть утеряны без последствий.

## 2. Целевые показатели (RTO и RPO)

| Категория данных | RPO (Recovery Point Objective)     | RTO (Recovery Time Objective)       |
| :--------------- | :--------------------------------- | :---------------------------------- |
| **Critical**     | Не более **5 минут**               | До **4 часов**                      |
| **Recoverable**  | Допускается утеря текущих индексов | **12 - 24 часов** (на перестроение) |
| **Ephemeral**    | **0**                              | Автоматически                       |

## 3. Стратегия резервного копирования

- **PostgreSQL:** Непрерывное архивирование WAL-файлов (Point-in-Time Recovery) и ежедневные снэпшоты.
- **Объектное хранилище (S3):** Использование механизмов репликации между регионами (cross-region replication) для защиты подписанных документов от потери ЦОД.
- Регулярные DR-учения для проверки готовности.
