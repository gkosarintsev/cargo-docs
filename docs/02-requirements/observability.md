# Наблюдаемость (Observability)

Инфраструктура Observability необходима для понимания состояния распределенной системы и быстрого расследования инцидентов.

## 1. Метрики (RED/USE)

- **RED (Rate, Errors, Duration) метрики сервисов:** Ключевые метрики API (RPS, частота ошибок, p50/p95/p99 latency).
- **USE (Utilization, Saturation, Errors) метрики инфраструктуры:** Загрузка CPU/RAM/Диска, заполнение очередей, системные ошибки.
- **Бизнес-метрики:** Количество заказов, активных водителей, объем обрабатываемых пакетов.

## 2. Логирование

- **Единый JSON-формат:** Все сервисы должны генерировать логи в структурированном JSON-формате.
- **Контекст корреляции:** Каждая запись лога содержит сквозные идентификаторы: `TraceId`, `SpanId`, `TenantId`, `UserId`.

## 3. Распределенный трейсинг (Tracing)

- Сквозные трассы обеспечивают отслеживание запроса от мобильного приложения через API Gateway до асинхронных потребителей событий (Kafka, БД). Позволяет быстро определять "узкие места" (bottlenecks) в микросервисной архитектуре.

## 4. Алертинг

Система оповещений разделена на уровни критичности:

- **P1 - Blocker:** Полный отказ критичной подсистемы (поиск, авторизация).
- **P2 - Critical:** Деградация метрик, ошибки на критичном проценте запросов.
- **P3 - Warning:** Приближение к инфраструктурным лимитам (место на диске, очереди Kafka).

**Каналы доставки:**

- Интеграции для оповещения дежурной смены: Opsgenie, PagerDuty, Telegram.
