# Безопасность (Security)

Обеспечение безопасности данных, строгая изоляция пользователей и защита от внешних угроз.

## 1. Требования к аутентификации

- **Протоколы:** Использование стандартов OAuth2 / OIDC для аутентификации пользователей и сервисов.
- **Токены:** Применение JWT с коротким сроком жизни и механизмом ротации (JWT rotation) для предотвращения компрометации.
- **Многофакторная аутентификация (MFA):** Обязательное использование MFA для административных доступов и подтверждения критичных финансовых операций (вывод средств, изменение реквизитов).

## 2. Модель разграничения прав

- **Изоляция тенантов (Multi-Tenancy):** Строгое разделение данных между различными организациями.
- **RBAC / ABAC:** Реализация контроля доступа на основе ролей (Role-Based Access Control) для базового разделения и на основе атрибутов (Attribute-Based Access Control) для гранулярной настройки политик с учетом multi-tenancy контекста.

## 3. Шифрование данных

- **Data at Rest (Данные в покое):** Все базы данных, резервные копии и объектные хранилища (S3) шифруются с использованием алгоритма AES-256.
- **Data in Transit (Данные в пути):** Весь внешний трафик шифруется по протоколу TLS 1.3. Взаимодействие между микросервисами внутри кластера защищается с помощью Mutual TLS (mTLS) для интеграций.

## 4. Защита от злоупотреблений

- **Rate Limiting (Ограничение скорости):** Защита всех API от перебора и избыточной нагрузки путем установки квот.
- **Защита от DDoS и WAF:** Использование Web Application Firewall (WAF) и anti-DDoS решений.
- **Anti-Scraping:** Защита от скрапинга базы грузов и контактов.

## 5. Неизменяемость журналов аудита

- **Immutable Audit Logs:** Все ключевые действия (создание/изменение заказов, входы в систему, финансовые транзакции) записываются в неизменяемый журнал аудита для обеспечения достоверности при расследованиях.
