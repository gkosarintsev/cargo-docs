# Поведенческий контракт: Детализация груза и управление торгами (Load Details & Negotiation)

## 1. Визуальные состояния экрана (PlantUML Salt)

### Состояние 1: Груз опубликован, ожидает откликов (Empty Bids)
Груз только размещен. Отображаются счетчик просмотров и индикатор покрытия подходящими машинами в радиусе.

![Load Details State 1](images/load-details-state1.svg)

### Состояние 2: Активные торги (Competing Offers)
Поступили конкурирующие ставки. Список автоматически ранжируется по выгодности ставки и рейтингу надежности перевозчика.

![Load Details State 2](images/load-details-state2.svg)

### Состояние 3: Модальное окно встречного предложения (Counter-Offer Modal)
Грузовладелец не согласен со ставкой перевозчика и выдвигает встречную сумму с ограничением по времени ответа (ADR-0010).

![Load Details State 3](images/load-details-state3.svg)

## 2. Детальные поведенческие контракты

- **Реалтайм обновление ставок (WebSocket)**: При поступлении нового оффера от перевозчика срабатывает событие `marketplace.offers.v1`. Строка добавляется в таблицу без перезагрузки экрана с зеленой анимацией подсветки.
- **Принятие ставки (Accept Offer)**:
  - Клик по кнопке «Принять ставку» отправляет `POST /api/v1/offers/{id}/accept` с заголовком `Idempotency-Key`.
  - Кнопка блокируется лоадером.
  - На бэкенде автоматически генерируется `Transport Order` со статусом `CREATED`, а все остальные офферы по этому грузу переводятся в статус `REJECTED (Offer Accepted)`.
  - Пользователь перенаправляется на экран активного заказа.
- **Встречное предложение (Counter-Offer)**:
  - Форма валидирует, что встречная ставка не превышает текущую ставку перевозчика.
  - Устанавливается `TTL` (по умолчанию 2 часа). Если перевозчик не ответил за 2 часа, предложение аннулируется (`EXPIRED`).
