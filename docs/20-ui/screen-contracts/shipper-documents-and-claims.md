# Поведенческий контракт: ЭДО, закрывающие документы и претензии (Documents & Claims)

## 1. Визуальные состояния экрана (PlantUML Salt)

### Состояние 1: Реестр электронных документов рейса (Clean Flow)
Все документы подписаны квалифицированной электронной подписью (КЭП) через операторов Диадок / СБИС, статус зеленый.

![Documents State 1](images/documents-claims-state1.svg)

### Состояние 2: Выставление коммерческого акта расхождений (Claim Filing / Торг-2)
При выявлении повреждения или недостачи комиссия получателя составляет акт расхождений, прикрепляет фотофиксацию и указывает сумму ущерба.

![Documents State 2](images/documents-claims-state2.svg)

### Состояние 3: Заморозка выплаты Escrow и арбитраж (Dispute & Escrow Freeze)
После подписания акта выплата перевозчику автоматически блокируется в сервисе Escrow до урегулирования убытка.

![Documents State 3](images/documents-claims-state3.svg)

## 2. Детальные поведенческие контракты

- **Электронная подпись (КЭП)**:
  - Интеграция с Госуслугами и провайдерами ЭДО.
  - При нажатии «Подписать КЭП» формируется XML-титул ЭТрН, вызывается плагин КриптоПро / Рутокен, либо облачная электронная подпись через СМС-валидацию ЕСИА.
- **Блокировка Escrow**:
  - При выставлении претензии `DisputeService` отправляет команду в `BillingService` на заморозку гарантийного депозита или ставки рейса.
  - Перевозчик не может вывести средства по данному рейсу до решения арбитража.
- **Страховой шлюз**:
  - Если сумма ущерба превышает франшизу, система автоматически генерирует и отправляет пакет документов (ТрН, акт расхождений, фото, выписка телеметрии) в API страховой компании.
