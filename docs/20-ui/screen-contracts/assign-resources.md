# Поведенческий контракт: Назначение ресурсов на заказ (Assign Fleet & Driver)

## 1. Визуальные состояния экрана (PlantUML Salt)

### Состояние 1: Форма подбора сцепки и водителя (Resource Matching Form)
Диспетчер выбирает тягач, полуприцеп и водителя из списка доступных. Система проверяет остаток смены по тахографу и валидность диагностических карт.

![Assign Resources State 1](images/assign-resources-state1.svg)

### Состояние 2: Конфликт назначения и превышение РТО (Constraint Violation Alert)
Попытка назначения водителя с недостаточным остатком смены блокируется. Предлагаются варианты: замена водителя, парный экипаж либо перенос окна погрузки.

![Assign Resources State 2](images/assign-resources-state2.svg)

### Состояние 3: Успешное закрепление и автоматическая выписка ЭПЛ (Success Assigned)
Ресурсы зарезервированы, сформирован электронный путевой лист (ЭПЛ), данные водителя отправлены на КПП склада.

![Assign Resources State 3](images/assign-resources-state3.svg)

---

## 2. Детальные поведенческие контракты

- **Валидация весогабаритных ограничений**:
  - Грузоподъемность полуприцепа должна быть строго больше либо равна массе груза (`trailer.payload_capacity_kg >= load.weight_kg`).
  - Тип полуприцепа должен соответствовать типу кузова груза (Тент, Реф, Изотерм).
- **Интеграция с тахографом и РТО (ЕСТР / 196-ФЗ)**:
  - Проверяется непрерывное время вождения (максимум 9 часов в сутки) и время ежедневного отдыха (не менее 11 часов).
  - При нехватке времени кнопка подтверждения блокируется с отображением алерта (State 2).
- **Автоматическая выписка пропусков**:
  - При подтверждении назначения сервис отправляет вебхук в WMS склада заказчика с паспортными данными водителя и номерами сцепки для автоматического открытия шлагбаума.
