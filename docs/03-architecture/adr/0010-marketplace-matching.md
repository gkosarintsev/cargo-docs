# ADR-0010: Алгоритм и архитектура Matching Engine маркетплейса

## Статус

Принято

## Контекст

Платформе требуется автоматический подбор и ранжирование релевантных перевозчиков и машин под новые заявки на перевозку грузов. Процесс должен быть достаточно быстрым, учитывать бизнес-правила и быть готовым к будущему усложнению логики.

## Рассмотренные альтернативы

1. **Дорогостоящий Black-box ML/AI матчинг с первого дня**: Требует больших затрат на разработку, длительного обучения моделей, непрозрачен для бизнеса на старте.
2. **Простой SQL-поиск по фильтрам**: Легко реализовать, но сложно поддерживать при росте числа критериев и правил ранжирования, высокие нагрузки на реляционную БД.
3. **Двухэтапный гибридный пайплайн**: Hard Constraints Filtering → Deterministic Rule-based Scoring с подготовкой данных для последующего ML-ранжирования.

## Решение

Мы выбираем **двухэтапный детерминированный пайплайн с плавной эволюцией в ML**.

### Обоснование

Архитектура Matching Engine будет состоять из двух этапов:

1. **Hard Constraints Filtering**: Быстрая фильтрация по жестким критериям (гео-радиус, тип кузова, грузоподъемность). Может быть реализована поверх индексов (например, Elasticsearch или PostGIS).
2. **Deterministic Rule-based Scoring**: Ранжирование отфильтрованных кандидатов по детерминированным правилам (рейтинг, пустой пробег, история надежности, предложенная ставка).

Этот подход позволяет запустить прозрачный и понятный для бизнеса механизм, который параллельно собирает обучающую выборку (какие предложения были приняты, а какие отклонены). В будущем блок Scoring может быть заменен или дополнен ML-моделью без изменения общего пайплайна.

## Последствия

### Положительные

- Быстрый Time-to-Market для бизнес-логики подбора.
- Прозрачность работы алгоритма на первых этапах (понятно, почему перевозчик на 1 месте).
- Сбор качественного датасета для будущих ML-моделей.

### Риски и их митигация

- **Риск**: Деградация производительности при увеличении числа правил ранжирования.
  **Митигация**: Использование in-memory структур или специализированных движков правил, а также кэширование профилей перевозчиков.
- **Риск**: Усложнение кода при добавлении новых критериев.
  **Митигация**: Использование паттерна "Strategy" или "Chain of Responsibility" для изоляции отдельных правил оценки.
