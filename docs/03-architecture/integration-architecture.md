# Интеграционная архитектура

## 1. Интеграционные протоколы и паттерны

- **Синхронный REST API**: Применяется для типовых CRUD-операций и интерактивного взаимодействия с партнерскими TMS системами в реальном времени.
- **Асинхронные Webhooks**: Используются для push-уведомлений внешних TMS систем о важных бизнес-событиях (смена статусов заказов, согласование офферов, поступление новых документов).
- **Event-Driven Integration (Kafka / AMQP bridges)**: Применяется для глубокой интеграции с крупными enterprise-партнерами, обеспечивая высокую пропускную способность и гарантированную доставку.

## 2. Надежная доставка вебхуков (Webhook Reliability Pipeline)

Архитектура механизма вебхуков строится на основе надежной очереди и автоматических повторов.

- **Схема доставки**: `Domain Event` → `Outbox` → `Kafka` → `Webhook Dispatcher` → `HTTP POST клиенту` → `Retry с Exponential Backoff` → `Dead Letter Queue (DLQ)` для необработанных или ошибочных отправок.
- **Защита вебхуков**:
  - Использование подписи `X-Signature-SHA256` для проверки подлинности источника.
  - Включение `timestamp` в payload для защиты от replay-атак (повторного воспроизведения).
  - Строгая валидация SSL-сертификата получателя при отправке POST-запроса.

## 3. Интеграция с телематическими системами (GPS Adapters)

- **Протоколы приема данных**: Поддержка различных стандартов: Wialon IPS, Omnicomm, EGTS, а также прямые HTTP/JSON push-уведомления от мобильных приложений водителей.
- **Изоляция сети**: Использование Stateless Ingestion Gateway для изоляции сетевого периметра. Входящий сырой трафик принимается, валидируется и конвертируется в унифицированные внутренние события без доступа к основной бизнес-логике платформы.
