# Архитектура безопасности

## 1. Эшелонированная оборона (Defense in Depth)

- **Периметр**:
  - Защита от DDoS-атак (использование Cloudflare или Qrator).
  - Web Application Firewall (WAF) для блокировки типовых атак (SQLi, XSS и др.).
  - TLS Termination на границе сети.
- **Шлюз (API Gateway)**:
  - Rate Limiting (ограничение частоты запросов) для защиты от брутфорса и перегрузки.
  - Валидация JWT токенов.
  - Проверка репутации IP-адресов.
- **Сервисный слой**:
  - Ролевая (RBAC) и атрибутная (ABAC) модели управления доступом.
  - Строгая проверка владения ресурсом на уровне бизнес-логики (например, проверка `organization_id == user.org_id`).
- **Слой данных**:
  - Шифрование дисков (LUKS/Transparent Data Encryption).
  - Шифрование критичных секретов непосредственно в БД (PII, платежные данные).
  - Хранение хэшей паролей пользователей с использованием алгоритма Argon2id.

## 2. Аутентификация и управление токенами

- **OAuth 2.0 / OIDC**:
  - _Access Token_: Короткоживущий JWT (время жизни ~15 мин) для доступа к ресурсам.
  - _Refresh Token_: Хранится в Redis, поддерживает автоматическую ротацию при использовании, применяется для получения новых Access токенов.
- **API Keys для внешних интеграций**:
  - Ключи хешируются (sha256) в базе данных (в открытом виде не хранятся).
  - Использование префиксов для идентификации ключей (например, `carg_live_...`).
  - Механизм мгновенного отзыва (revocation) скомпрометированных ключей.

## 3. Изоляция тенантов (Multi-tenant Security)

- **Разделение данных**: Применение Row-Level Security (RLS) на уровне базы данных или Application-level tenant filter в ORM для гарантии изоляции данных разных организаций-клиентов.
- **Защита от уязвимостей**: Проактивная защита от BOLA (Broken Object Level Authorization) и IDOR (Insecure Direct Object Reference) уязвимостей путем обязательной проверки прав субъекта на объект при каждом обращении к API.
