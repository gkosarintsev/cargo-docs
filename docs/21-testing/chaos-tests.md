# Тестирование хаосом (Chaos Engineering)

С помощью **Chaos Mesh** или **Gremlin** эмулируются инфраструктурные сбои на Staging (и выборочно на Production) для валидации устойчивости архитектуры.

## Сценарии инъекции сбоев
1. **Падение БД**: Убийство Primary ноды PostgreSQL под нагрузкой.
   - *Ожидание*: Patroni делает failover < 30 сек. Чтение не прерывается, запись приостанавливается на 30 сек без потери данных.
2. **Деградация сети**: Добавление Network Latency (2000ms) к кластеру Kafka.
   - *Ожидание*: Outbox Worker замедляется, но основное API отвечает клиентам мгновенно.
3. **Падение внешнего сервиса**: Отключение геокодера (DaData/Яндекс).
   - *Ожидание*: Маршрутизатор использует локальный Fallback-кэш адресов.
4. **Частичный отказ OpenSearch**: Убийство половины Data-нод.
   - *Ожидание*: Реплики (Replica Shards) берут на себя чтение, кластер уходит в состояние Yellow, пользователи не замечают сбоя.
