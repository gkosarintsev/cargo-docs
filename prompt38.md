## Контекст

Переходим к разделу **20-ui** (Этап 13).
Важнейший принцип из §35 master-prompt: **«Документируй не графический дизайн, а behavior contracts экранов»**.
Каждый экран описывается как строгий контракт взаимодействия: пользовательские действия, триггеры вызовов API, изменения локального и серверного состояния, публикация событий и реактивные обновления интерфейса по WebSocket.

Язык — **русский**.

---

## Общий формат описания UI Behavior Contract

Для каждого экрана специфицируй цепочку:

```
Screen / View State
  ↓
User Action (Клик / Ввод / Драг-н-дроп)
  ↓
Client Validation & Optimistic UI Update
  ↓
API Request (Endpoint, Method, Headers: Idempotency-Key)
  ↓
Server State Transition & Domain Event
  ↓
Realtime Event (WebSocket / SSE push)
  ↓
UI State Reconciliation & Final View Update
```

## Спецификация файлов Screen Contracts

### 1. `create-load.md` (Экран публикации груза)

- **Состояния экрана**: `Initial Form`, `Validating Addresses`, `Calculating Recommended Price`, `Publishing`, `Published Success`.
- **Поведенческие контракты**:
  - Ввод адреса погрузки/выгрузки → автокомплит с геокодингом → отрисовка маршрута на миникарте.
  - Изменение веса/типа кузова → фоновый запрос `GET /api/v1/pricing/estimate` → отображение виджета «Рекомендуемая ставка: 110 000 – 125 000 ₽».
  - Клик «Опубликовать»: блокировка кнопки, генерация `Idempotency-Key`, `POST /api/v1/loads` → оптимистичный показ груза в списке со статусом `Синхронизация...` → переход в карточку груза.

### 2. `load-search.md` (Экран поиска и фильтрации грузов)

- **Состояния экрана**: `Loading Skeleton`, `Results List`, `Map View Split`, `Empty State`, `Error State`.
- **Поведенческие контракты**:
  - Изменение фильтров (радиус, кузов, дата) → дебаунс 300мс → `GET /api/v1/loads` с cursor-пагинацией.
  - Бесконечный скролл (Infinite Scroll) без смещения позиции при поступлении новых грузов.
  - Real-time бейдж «+3 новых груза по вашему поиску» (по WS) без сбивания фокуса пользователя.

### 3. `offer-management.md` (Экран торга и работы с откликами)

- **Поведенческие контракты**:
  - Карточка оффера: рейтинг перевозчика, предложенная ставка, таймер истечения срока действия.
  - Кнопка «Встречное предложение» → открытие модала → `POST /api/v1/offers/{id}/counter` → мгновенный перевод карточки в статус `Ожидает ответа перевозчика`.
  - Кнопка «Принять предложение»: диалог подтверждения с реквизитами → `POST /api/v1/offers/{id}/accept` → мгновенная блокировка остальных офферов со статусом `Отклонено системой` → переход в мастер оформления `TransportOrder`.

### 4. `dispatcher-board.md` (Диспетчерский пульт / Active Fleet Board)

- **Поведенческие контракты**:
  - Split-view: Слева список активных рейсов с цветовой индикацией (Зеленый — по графику, Желтый — риск задержки, Красный — авария/срыв), Справа интерактивная карта с машинами.
  - WebSocket подписка на телеметрию: плавное перемещение маркера фуры по карте по мере поступления GPS-точек (интерполяция движения).
  - Клик по алерту «Поломка в пути» → центрирование карты на машине, раскрытие панели экстренной связи и кнопки «Назначить резервный тягач».

### 5. `shipper-dashboard.md` (Главный дашборд грузовладельца)

- Сводные KPI виджеты (активные грузы, в пути, ожидают оплаты), быстрый доступ к созданию груза, лента последних событий по активным доставкам.
